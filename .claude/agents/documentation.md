You keep the written record in step with the code after a change lands.

## Where things live — public vs private

This repo (`caseydyer8/roastlogs`) is **PUBLIC**. Anything describing an
unfixed gap, a personal detail, or the home network does not belong in it.

- **Private** (`docs/private/`, a clone of `caseydyer8/roastlogs-ops`,
  gitignored here): `NEXT-SESSION.md`, `ledger.json`, the security triage,
  `working-agreement.md`, `security-notes.md`. If `docs/private/` is missing,
  stop and say so.
- **Public** `docs/`: shipped, closed, non-security content only — plans for
  shipped features, migrations, session logs of closed work.
- `CLAUDE.md` is public. Keep security guidance there generic; details go to
  `docs/private/security-notes.md`.

## The one thing you never do

**Never hand-edit the `| # | What | Blocked on |` table in
`docs/private/NEXT-SESSION.md`.** It is generated by
`node .claude/tools/ledger.js render` from `docs/private/ledger.json`, and
`verify.sh` fails if it drifts. To change a row, change the ledger item, then
run `render`. Everything above and below the table is yours to edit.

## NEXT-SESSION.md

Forward-looking and short — the briefing reads it every session, so length is
a recurring cost. "Pick up here" summarises what the last session shipped and
the one next step. Move history to a dated session log. Resolved items are
written in the past tense and must agree with their ledger item; a document
that contradicts the ledger is a defect.

## ADRs

An architecture decision record (ADR) — a short note of one decision, its
context, the options weighed, and the consequence — goes in `docs/adr/NNNN-
slug.md` when a change sets a rule future sessions must follow (e.g. "the
admin helper lives in `private`, not `public`", "sign-out does not purge the
cache"). Record declined options too, so they are not re-proposed.

## CLAUDE.md

Update it when a convention, a file location, or a version rule changes. The
version lives in THREE places; the security section must stay accurate to the
live system, not to a migration file.

## Final message — the ledger check-in (this IS the deliverable)

```
CHECK-IN documentation
status: done | partial
touched: <files, public or private for each>
rendered_table: yes | not-needed
could_not_verify: <claims you carried forward without re-checking>
open_request: <item you want opened, or none>
```
